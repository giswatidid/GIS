Edit KMZ files online

Use this workflow when geometry matters more than preserving every presentation feature of the original KMZ.

Before you edit a KMZ file

A KMZ file is a ZIP archive that normally contains one or more KML documents and may contain icons, images or other resources. EditPolygon concentrates on geometry and feature properties. Keep the original KMZ and verify styling, folders, icons, labels, altitude information and embedded resources in the destination software after export.

Best suited to EditPolygon

Polygon and MultiPolygon boundaries, holes, names, common attributes, validation, repair and format conversion.

Verify elsewhere

Complex KML styles, NetworkLinks, tours, models, GroundOverlays, altitude modes and application-specific extensions.

1. Open and review the KMZ

  1. Select Open.

    Choose the .kmz file. EditPolygon decompresses the archive in the browser and reads supported KML geometry.

  2. Review import preview.

    Confirm the expected number of files and features. If the file is very large, choose an import mode that matches your need: full editing for exact coordinates, optimised editing for speed, or a reference overlay when editing is unnecessary.

  3. Import and Fit.

    After import, select Fit to frame the geometry. Expand the layer in Layers.

2. Inspect every polygon before editing

Select each important feature and check the Inspector. Confirm the feature name, Polygon or MultiPolygon type, part count, holes, area and bounds. A layer may contain several placemarks that overlap or represent different operational purposes.

3. Edit the geometry

Move or reshape boundaries

Select Edit polygon. Drag red vertices, click green midpoints to insert coordinates, and use snapping when boundaries must meet. Press Done when the shape is correct.

Edit coordinates directly

Open Geometry code in the Inspector to review the GeoJSON representation of the selected KMZ polygon. This is useful for precise coordinate replacement or diagnosing an unexpected ring. Format the JSON, review errors and apply only after confirming longitude/latitude order.

Use geometry tools

Use Geometry tools to merge adjacent placemarks, split a polygon, repair a boundary, fill or create holes, offset, simplify or smooth. Preview operations where available and use Undo if the result is not what you expected.

4. Check and repair geometry

Open GIS → Check & fix geometry. Geometry Health separates shape-preserving cleanup from repairs that may change geometry. Locate reported issues on the map, apply safe fixes, preview any consequential repair and create a repaired layer only after the result looks correct. The imported KMZ layer remains untouched by default.

5. Export back to KMZ or KML

  1. Choose scope.

    All exports every project feature; Selected exports only the current selection; Visible excludes hidden features.

  2. Select KMZ.

    Use KML when an uncompressed text file is preferable. Use KMZ when the receiving workflow expects a packaged file.

  3. Set filename and precision.

    Preserve full precision unless you have a specific compatibility or file-size reason to round coordinates.

  4. Export and verify.

    Open the output in the intended destination application and compare it with the original and the EditPolygon map.

Common KMZ problems

The file opens but no polygon appears

The archive may contain only points, lines, overlays, NetworkLinks or unsupported KML constructs. Confirm the source contains Polygon or MultiGeometry polygon content.

The geometry appears in the wrong location

KML uses longitude, latitude order in WGS 84. A file generated with swapped axes or projected coordinates can appear displaced.

The output is valid but looks different

The receiving application may apply different styles, altitude handling or folder logic. Compare geometry separately from presentation.

The KMZ is too large or slow

Hide unneeded layers, keep complex layers collapsed, use optimised import when exact vertex preservation is not required, and edit one feature at a time.

KMZ export checklist
  • Expected polygons and holes are present.
  • Names and required properties are retained.
  • Geometry passes validation.
  • Correct export scope is selected.
  • Output opens in the destination software.
  • Styling, folders and embedded resources have been checked separately.
