Geometry Health

The normal workflow is Check → Understand → Fix safely → Review changes → Create repaired layer.

What Geometry Health checks

Geometry Health checks the structure of vector features rather than guessing whether the mapped information is factually correct. It supports points, lines, polygons and their multipart equivalents. Standard checks include missing or invalid coordinates, repeated vertices, collapsed geometry, polygon ring problems, self-intersections, invalid holes and invalid multipart relationships.

Validity is not accuracy.

A feature can be technically valid and still be mapped in the wrong place or represent the wrong real-world boundary. Always compare important repairs with the source data.

A normal open LineString is valid line geometry. Geometry Health does not treat a line as broken merely because its endpoints do not meet.

1. Open Geometry Health

Choose GIS → Check & fix geometry. You can also open it from the GIS actions for a layer. The selected layer is used when possible, but you can change the layer inside the Geometry Health panel.

2. Choose what to check

Select the layer and scope. You can check All features, the current Filtered records, features currently Visible in the map extent, or only Selected features. The scope is shown again before a repaired layer is created so a partial result is not mistaken for the complete source dataset.

3. Understand the results

After the check, every feature is placed in one main result category so the totals are easy to understand:

  • Ready — no checked geometry problem was found.
  • Safe to fix — Geometry Health found cleanup that preserves the represented shape, such as exact repeated vertices or ring direction.
  • Needs review — a proposed repair may change geometry structure or shape and must be reviewed.
  • Manual review — the software can identify a concern but should not decide the correct data interpretation for you.

Select an issue to locate the affected feature on the map. Where the validator can identify an exact problem location, it marks that location as well. Open Technical detail only when you need the underlying rule or geometry-engine diagnostic.

4. Fix safe issues

Use Fix safe issues to apply only conservative, shape-preserving cleanup. Geometry Health deliberately does not put ambiguous operations such as deleting likely duplicate features into this bulk action.

The layer is rechecked after cleanup, so a feature may move from Safe to fix to Ready while a separate review issue remains visible.

5. Review consequential repairs

For an issue that can change the geometry, choose its repair action to create a proposal. Geometry Health displays the original and proposed result on the map and summarises consequences such as geometry-type changes, vertex changes and relative area or length changes.

Repairs such as closing an open polygon ring, removing an invalid hole, dropping a collapsed component or making a self-intersecting polygon valid must be accepted explicitly. High-consequence results are identified rather than silently included in a bulk repair.

Robust polygon repair

When available, Geometry Health uses the GEOS geometry engine for polygon validity checking and MakeValid repairs. If that engine cannot load, the panel reports the degraded state and labels the less-comprehensive fallback rather than presenting it as equivalent.

6. Optional layer rules

Standard geometry validity and dataset-specific topology rules are different questions. Open Advanced rules only when they make sense for your data. Optional checks include exact duplicate features, polygon overlaps, line self-crossings and dangling line endpoints.

For example, overlapping polygons may be an error in a parcel layer but completely legitimate in a hazard-zone layer. Geometry Health therefore reports polygon overlap only when you ask for that rule.

7. Create the repaired layer

Choose Create repaired layer when you are satisfied with the accepted repairs. EditPolygon creates a normal project layer with the source schema, CRS and display metadata carried forward where appropriate. The original layer remains untouched by default.

The new layer records Geometry Health provenance, including the source layer, scope, rules, before-and-after counts, geometry-engine state, accepted repairs, warnings and unresolved issue summary. Creating the layer participates in the normal project history so it can be undone.

8. Export a validation report

Use the report controls to download JSON for detailed machine-readable results or CSV for an issue-oriented table. Reports are useful when geometry quality needs to be reviewed outside the editor or documented before further analysis.

Troubleshooting

Geometry Health says the coordinates may use the wrong CRS

Do not repair the shape merely to make the numbers look like longitude and latitude. Check the layer CRS first. Coordinates outside the expected WGS 84 range are treated as a manual CRS warning because assigning or transforming a CRS is a separate GIS operation.

A self-intersection repair changes Polygon to MultiPolygon

That can be a legitimate result of making a crossing boundary topologically valid. Review the map preview and the reported change before accepting it. A geometry-type change is treated as consequential.

A possible duplicate feature is reported

Geometry Health does not automatically delete it. Confirm whether the records are genuinely duplicates or represent separate real-world records that happen to share geometry.

The robust geometry engine is unavailable

You can still see deterministic structural checks. If a repair uses a fallback, Geometry Health labels the repair engine and warning in the preview. For important polygon topology, retry when the robust engine is available or verify the result in another GIS package.

Completion check

Before continuing with joins, overlays or export, confirm that the repaired layer has the expected feature count, no unexplained geometry-type changes, acceptable area or length changes, and no unresolved issue you intended to fix.
