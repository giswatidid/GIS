Repair invalid polygon geometry

A controlled repair workflow for Polygon and MultiPolygon files.

What makes a polygon invalid?

A polygon can look reasonable on a map but fail geometric rules required by another GIS. Common problems include rings that are not closed, duplicate consecutive coordinates, self-crossing boundaries, holes outside their shell, malformed MultiPolygon nesting and degenerate rings with too few distinct positions.

Technical validity

The coordinate structure meets geometry rules and can be processed by common GIS libraries.

Operational correctness

The boundary represents the real area you intended. Validation cannot determine this for you.

1. Open the validator

Choose More → Validate / repair polygons. You can validate the current project without exporting first, or choose a separate supported file.

2. Choose the source

  • Use current project polygons checks the geometry currently visible in the editor model.
  • Choose files checks a GML, KML, KMZ, GeoJSON, JSON, CSV, WKT/TXT or zipped Shapefile separately.
  • Clear removes the current validation source and results.

3. Review every reported issue

IssueWhat it meansWhat to inspect
Unclosed ringFirst and last coordinates differ.Confirm closing the ring does not create a long unintended edge.
Duplicate consecutive vertexAdjacent positions are identical.Usually safe to remove, but check very small features.
Self-intersectionNon-adjacent boundary segments cross.Repair can split or reshape the boundary; inspect carefully.
Invalid holeA hole is outside or conflicts with the exterior.Determine whether it is a hole, a separate polygon or erroneous data.
Degenerate ringToo few distinct points or near-zero area.Decide whether to delete or reconstruct it.
Possible duplicate featureTwo features appear geometrically identical.Check identifiers and attributes before removing one.

4. Select repairs deliberately

Recommended selects the lower-risk fixes identified by the validator. All can include more aggressive changes and should not be treated as a one-click guarantee. Use None to clear selections and choose fixes manually.

Keep an untouched source copy. Repair can change coordinate count, ring order, part structure and area. For important boundaries, record the issues and fixes applied.

5. Apply, preview and verify

  1. Choose the output format and filename.

    Use the format required by the receiving system.

  2. Apply selected fixes.

    The output preview is generated without automatically replacing the current project.

  3. Inspect the geometry.

    Import the fixed result into the map or download and open it in the destination GIS.

  4. Compare area and bounds.

    Unexpected changes can indicate an over-aggressive repair.

Repair active versus the validator

Repair active in Geometry tools is convenient for the selected polygon. The full validator is better when you need a documented list of issues, control over fixes, a separate source file or a repaired download.

Preventing invalid geometry

  • Use snapping when boundaries should meet.
  • Avoid dragging an edge across another edge.
  • Do not delete so many vertices that a ring collapses.
  • Inspect holes after merge, split, cut or repair operations.
  • Validate after geometry operations and before final export.
  • Use Undo immediately when a preview or applied change is unexpected.

Troubleshooting

The validator reports no issue, but another system rejects the file

The problem may involve CRS metadata, unsupported attributes, format schema rules, altitude, encoding or application-specific constraints rather than polygon validity.

Repair changes the polygon too much

Undo or return to the original file. Fix the boundary manually at a close zoom, then validate again.

A self-intersection repair creates multiple parts

The crossing may define more than one valid area. Decide whether the intended result is a Polygon, MultiPolygon or a manually redrawn boundary.

The same issue returns after export

Check whether coordinate rounding, format conversion or the destination application is reintroducing or interpreting the geometry differently.

Repair checklist
  • Original file retained.
  • Every issue description reviewed.
  • Only justified fixes selected.
  • Area, bounds, holes and parts compared after repair.
  • Output reopened in the destination system.
  • Repair decisions documented for important data.
