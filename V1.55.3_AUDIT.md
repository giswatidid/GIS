# v1.55.3 full repository and map-runtime audit

## Scope

The v1.55.3 audit used the full GitHub repository ZIP supplied after v1.55.2 as the authoritative baseline. The goal was not to add GIS features. The goal was to remove the temporary OpenLayers/Leaflet compatibility architecture, find source-order hazards, retire obsolete repository files and leave repeatable automated checks.

## Repository inventory

Baseline inventory:

- 139 tracked files in the supplied tree before cleanup.
- `docs/assets/editpolygon-app.js` is approximately 22,500 lines and remains the main architectural risk area because later releases historically wrapped or reassigned functions in source order.
- The repository root contained 31 historical `GIS_*` release/hotfix notes and `V1.55.*_CHANGED_FILES.md` manifests from the recent migration alone.

Those historical root documents were useful during individual patches but had become maintenance noise. They are removed in v1.55.3 and consolidated into:

- `ARCHITECTURE.md`
- `CHANGELOG.md`
- this audit
- the current `V1.55.3_CHANGED_FILES.md`
- `CRS_VALIDATION.md` for the still-relevant CRS validation detail.

No deployable guide, icon, SEO verification file, redirect, worker, runtime module or current stylesheet was removed merely because it looked old. The cleanup intentionally distinguishes historical release paperwork from files still used by the static site. A new `.gitignore` also excludes dependency folders, Python caches, logs, editor/OS metadata and local packaging scratch directories so the same classes of local clutter are less likely to be committed later.

## OpenLayers/Leaflet compatibility audit

### Removed

OpenLayers mode no longer has any of the following:

- `.editpolygon-leaflet-compat` DOM target;
- synchronized hidden `L.map(...)`;
- `legacyMap`;
- `syncLegacy`;
- `getLegacyMap`;
- `__peGetLeafletMap`;
- `__polygonEditorLeafletMap`;
- `parityBridge` / `mapParityBridge`;
- compatibility-map click capture/forwarding;
- OpenLayers CSS rules targeting compatibility Leaflet panes.

`createOpenLayersRuntime()` contains no `L.*` calls. A requested OpenLayers runtime therefore does not instantiate a Leaflet map. Leaflet is still loaded by the page because it remains the default/fallback transition engine for later migration stages.

### Map adapter consolidation

Both engines now expose the common tile/WMS layer creation contract. Built-in basemaps and GIS service layers use `MAP_RUNTIME.createTileLayer()` / `createWmsLayer()` rather than branching into direct `L.tileLayer` calls from application code.

Reference GeoJSON/tile/raster display remains on the v1.55.2 map-runtime path.

### Legacy renderer confinement

The monolith still contains historical Leaflet renderers because Leaflet remains a supported transition engine. v1.55.3 explicitly guards the early renderer, the v1.30 performance renderer and the v1.41 label renderer from executing in OpenLayers mode.

The authoritative current renderer is `cachedRenderMap`.

The previous v1.53 non-spatial-table wrapper reassigned `renderMap` *after* the cached renderer. v1.55.3 removes that late wrapper and handles `file.tableOnly` directly inside `cachedRenderMap`, reducing another source-order override.

## Source-order audit

A heuristic scan of `editpolygon-app.js` finds **206 named functions with more than one declaration/reassignment site**. This is expected from the application's long history of incremental patches, and not every wrapper is a bug: many are deliberate enhancement wrappers that capture the previous implementation before replacing it. It is nevertheless substantial architectural debt and a concrete source-order risk.

The audit therefore distinguishes **critical runtime authority** from intentional older wrappers.

Automated checks now fail if any later code overwrites these ordinary click-selection functions:

- `featuresAtLatLng`
- `featureHitAtMapPoint`
- `parametricCircleHitAtMapPoint`
- `applyMapFeatureSelection`
- `selectFromMapClick`

They also fail if any `renderMap = function ...` appears after the authoritative `renderMap=cachedRenderMap` binding.

This directly protects against the class of bug that caused true circles to render correctly and work with spatial selection while remaining impossible to click-select.

## Direct map escape-hatch audit

Production application code is checked for transitional direct calls through the old `map` handle:

- `map.addLayer(...)`
- `map.removeLayer(...)`
- `map.hasLayer(...)`
- `map.getPane(...)`
- `map.createPane(...)`

These calls are no longer permitted in the application-level transition layer. Leaflet-only functionality that still needs panes obtains the native Leaflet map explicitly from `MAP_RUNTIME.getNativeMap()` and is engine-guarded.

Direct `L.*` implementation code still exists for the Leaflet engine and will be removed in the later Leaflet-removal release, not hidden or pretending to be engine-neutral.

## Static deployment audit

`docs/DEPLOYMENT.md` incorrectly referred to `assets/editor.css`; this is corrected to `assets/editpolygon.css`.

The Cloudflare `_headers` CSP was also stale:

- OpenLayers 10.9.0 is loaded from jsDelivr but jsDelivr was not listed in `script-src`/`style-src`.
- The app intentionally supports arbitrary public HTTPS GIS services, but `connect-src` was restricted to a small hard-coded provider list.

v1.55.3 updates the CSP to allow the pinned CDN sources and direct HTTPS GIS/image connections while retaining restrictions such as `object-src 'none'`, `frame-ancestors 'self'`, HSTS and the existing browser-permission policy.

## Files deliberately retained

The audit retained:

- all current application/GIS modules and workers;
- guide pages and their referenced WebP assets;
- static-site pages;
- favicons/icons/social preview;
- Bing/Yandex verification;
- `robots.txt`, `sitemap.xml`, manifest;
- `_headers` and `_redirects`;
- `docs/DEPLOYMENT.md`;
- `CRS_VALIDATION.md`.

These files are either referenced by the deployable site, support deployment/discovery, or contain still-current technical validation.

## Automated enforcement added

`scripts/audit-runtime.mjs` now checks:

- v1.55.3 package/cache version;
- absence of compatibility-map tokens in production runtime/CSS;
- absence of Leaflet calls inside `createOpenLayersRuntime`;
- presence of the native OpenLayers DOM overlay pane;
- source-order protection for critical selection functions;
- no renderer override after `cachedRenderMap`;
- OpenLayers guards on historical Leaflet renderers;
- no transitional direct `map.add/remove/hasLayer/getPane/createPane` calls;
- absence of old root release-note/change-manifest clutter;
- presence of consolidated current documentation;
- local HTML asset/link existence;
- unreferenced top-level runtime assets and guide images, so obsolete deployable assets cannot quietly accumulate.

The normal `npm run check` command runs this audit before the unit/integration tests.

## Deliberately deferred

v1.55.3 does **not**:

- make OpenLayers the default;
- remove the Leaflet library or Leaflet runtime;
- delete all historical implementation wrappers from the monolithic application;
- redesign project/history/schema/CRS models;
- add new raster analysis.

Those are separate risk boundaries. The next planned stage is the full OpenLayers parity review before OpenLayers becomes the default.
